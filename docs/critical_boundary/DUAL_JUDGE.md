# Qwen 双职责协议：质量筛查与逐事件预标注

版本 dual-v1，2026-10-17，开发适配器。未默认接管正式计分。

## 输入与职责

数据侧协议预先固定对象、事件定义、观察窗、来源版本。配置、仿真状态、接触记录和临界搜索产生参考答案与距离。参考答案、临界点所在侧和未来事件时刻不传给视觉裁判。

1. **质量筛查**：输出 measurable/unmeasurable/uncertain，损坏原因、自报置信度、证据时间和物理异常。清楚可见的穿模等物理错误不自动等于不可测；正常遮挡和出画不等于身份丢失。
2. **事件判读**：每个预登记事件单独输出 yes/no/not_observed/uncertain、自报置信度、至少两个时间点的证据和理由。no限于观察窗；未看到落地不推出永远不落地。下落不要求落地。

本轮对象级质量检查以完整观察窗为单位。若质量未通过，三个事件暂缓预标注并交人工判断可保留的早期事件；当前代码还没有自动定位损坏起始时刻及自动保留损坏前事件，不应声称已实现该能力。

## 路由

开发阈值固定为0.90（含），仅是自报置信度门槛，不是校准后的正确概率。

- 质量高置信可测，并且事件高置信、证据有效、逐帧观察及轨迹检查支持该标签：preannotated。
- 低置信、证据不足、未知、格式错误或矛盾：review，保留候选与原因。
- 高置信且至少两个时刻支持融合/身份丢失/严重损坏造成不可测：reject_measurement；依赖该目标的事件blocked_quality。仍是自动质量候选，可靠性需要独立验证。
- 原视频不删除；生成失败保留总分母。人工待审不默认为0，也不能从分母静默删除。
- 事件分别路由：地面接触复核不影响独立成立的下落预标注。反演另报适用性和完成覆盖率，本模块不输出反演成功。

当前 supported/airborne/ground 的几何检查仍采用固定相机桌面开发规则，见WINDOW_AWARE_JUDGE.md；不作为20类场景通用定律。质量拒绝依赖VLM自报，尚未完成独立人工验证。

## 留档与审核

逐帧观察、质量输出、各事件输出保存在raw JSON；预标注与review_queue按事件拆分。人工填写标签、证据、审核人后才升级为确认标签。高置信预标注不能直接宣称人工真值。

本轮开发追加dual-v1.1后处理：明确形式`Frame N: 说明`可提取整数N，同时保留raw_evidence和format_normalization记录；未明确给出的时间不猜测。所有结果用同一后处理重算，原模型回答不修改。逐事件引用还要包含相应的可见状态；下落至少引用两个空中时刻，不能只引用初始桌面和最终地面。此规则为保守开发检查，可能增加复核负担，不是通用识别准确性保证。

本轮复用T08/T13五输入的SAM2轨迹和同一加密抽帧，改变输出提示与路由。三个源视频、两个前缀不是五条独立轨迹；均已用于开发，且无明确生成损坏样本。因此能观察事件预标注效果，不能据此证明垃圾视频检出率。正式使用前须在此前生成坏样本及独立样本上另验质量筛查。
