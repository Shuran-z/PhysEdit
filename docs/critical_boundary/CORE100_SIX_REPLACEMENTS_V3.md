Near是按归一化距离确定的子集，不是要求全部100条都进入Near。距离区间横跨分界时保留“距离分层不确定”，仍可用于适用的事件和配对评测。

T03_C02已有正确原种子的数值区间 `[0.1, 0.4]`。未放行的原因是手机在关键阶段从画面下缘出画，尚不能从该固定视角可靠确认“越缘下落”。这不是数值尚未求出，也不把出画当作跌落。

作者进一步确认：主判据可采用“越缘并开始下落”，不要求接触地面。脱离／越缘、向下运动和落地分别记录；落地不可见不会否定已经可判的前两项。T03_C02复核的是小黑手机的越缘阶段，不是后来从上层滑落的大蓝书。原cam03在这一阶段存在下缘裁切，同次仿真的cam02能显示该过程；尚未获得明确的第7条输入替换决定，因此原输入保留。

上述数字是参考接入数量，不是模型准确率。完整EventExact、模型响应曲线的BoundaryError和物理反演仍需各自注册、生成输出和有效测量，不能由两端参考或一次预检代替。

逐条收口核查已重读本地186份绑定来源快照及全部输入绑定，并重新计算100条的归一化距离与分层。Near的14条中，参考负类6条、正类8条，评分时两类仍各占一半。T11_C03使用原联合G扫描路径的无量纲坐标和跨度1；它不是某个单独物理参数的临界效应，不能与速度、摩擦等原始单位直接混算。

## 裁判接口补充

新导出的裁判任务使用`registered-observations-v2`，保留事件定义中的对象名单、指定接触配对、时域语义与不确定性要求。上述信息仅描述判读任务，不包含参考答案、参数侧别或临界距离。旧已登记任务不改写。

事件预测需回传`event_contract_sha256`与实际抽帧的`times_s`，防止同一视频在对象范围、末态／曾发生定义或跟踪配置改变后误用旧预标注。Qwen适配器已输出这些字段。末态事件若只引用早期帧，或全窗否定只引用中间帧，送复核；不把它自动修成另一事件标签。已有人工最终确认规则和失败分母不变。

## 生成模型的时长检查

上面的`prepare`只是导出任务，不证明模型支持所需时长。实际生成前使用`physedit.runners.boundary_registered prepare`绑定模型的原生帧数、帧率和执行环境，先检查`PRECHECK.json`中的`native_generation`。

目前登记的本地MiniMax-H3执行器固定124帧、24 fps，覆盖5.125秒；这版100条中有14条需要更长的观察窗口，因此该执行器只有86条时长兼容。完整批次会在加载模型前拒绝启动，不能将这14条算成生成模型的物理判断错误，也不能为适配执行器而缩短参考窗口。Cosmos3 Nano的已登记189帧、24 fps配置在时长上覆盖全部100条；这只是配置检查，尚非实际推理验证。

适配器保留模型完整原生输出，裁判仅查看每条原定的观察窗口。不会通过补帧、循环、重定时或串接视频补足时长；条件图、prompt、物理参数、参考真值和旧任务不改变。新模型配置写入独立目录，旧登记文件不改写。

```powershell
python -m physedit.runners.boundary_registered prepare `
  --boundary-spec review/core100_v3_new_run/spec.json `
  --out review/core100_v3_native_h3 `
  --model minimax_h3 --model-dir <执行主机上的本地权重目录> `
  --runtime-json <执行主机上的环境配置JSON>
```

此命令不加载权重、不启动GPU。必须先处理不兼容项，不能将仅导出任务说成已完成生成实验。实际运行配置应在执行主机准备，不能直接沿用其他主机的绝对路径。
