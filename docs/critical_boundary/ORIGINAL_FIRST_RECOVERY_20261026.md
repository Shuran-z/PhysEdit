V11 `search` 阶段从笔记本触地轨迹取3个落点锚点，各遍历4个 x 偏移和2个 y 偏移，即每个背景/重力24个手机位置候选。`formal` 阶段要求候选 valid 且 full_chain，挑选手机位移最接近0.10m的候选，并把该样本ID写为 `calibrated_source_id`。

因此，此字段能证明手机位置经过仿真搜索，却不能单独提供A初速、B支撑边距、C横向位置三个事件边界。

正式三分支来自 `base.specs_for(g)`，目前读取的函数中是显式常量：

|族|三分支设计输入|解释|
|---|---|---|
|A|基础速度乘0.72、0.84、0.96，并受速度上限裁剪|中间项是设计中心；此函数不执行临界求解|
|B|0.085、0.050、0.020m|支撑边距，不能把0.050m直接宣称为求解结果|
|C|0.145、0.080、0.015m|扫描坐标；实际手机y为校准位置加该值减0.080m|

这一发现仅限所核查代码路径；不能证明历史上不存在产生这些常量的其他计算或手工校准。下一步追踪这些常量的原始推导/历史日志和实际发布修订。已有补算距离保留，不因此重新渲染或重新启动整批搜索。

## 剩余工作的边界

1. 原值已登记的族：核对发布身份，直接使用原值距离。细化和复现单列。
2. 仅有设计中心的族：优先查中心值的生产来源。先找，不自动补算。
3. 仅有补算距离的族：现有数值保留；原记录恢复状态独立追踪。
4. 必要补算：只有明确原搜索来源未保存/无法恢复，或用户新选事件没有对应原边界时，才进入必要清单。
5. T19旧发布继续停用；T14采用用户指定旧版，T14S单列。

当前尚未获得覆盖全部发布样本的必要补算总数。原先1067项是补充计算未完成数，不能当作必须补齐的临界点数；63.53%也不是20场景原值恢复完成率。
