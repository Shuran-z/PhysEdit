# Core100接触目标补充协议 v1

2026-10-27，作者明确选择“采用新版本接触协议”。原协议、视频、提示和人工记录保留；本补充不恢复或虚构缺失的历史终态判据。

## 新登记的十条

- **T12_C01–C05**：同一原订书机与原纸巾盒在登记窗内至少发生一次物理接触。源合同已有E2接触节点。本次不定义运动位移阈值，不将动量传递或持续滑动推断为已接触。
- **T13_C01–C05**：分别判断原驱动书→原接力书、原接力书→原饮料盒接触；两个首次接触按原生产队列要求非递减，比较 `(frame_index, physics_step_index)`。若原记录只有帧号，同帧先后无法细分，必须保留证据粒度，不能编造子步顺序。此任务不包含饮料盒跌落终态。

接触真值来自仿真原生接触。空列表只有在确认接触遥测确实开启且覆盖完整观察窗时才能表示未接触；没有contacts字段是缺失，不能填负。T12旧状态无该遥测，需要精确源配置的补充观测并逐帧核对原轨迹；无法对应时保持待准入。重放遥测必须明确标记，不能称为原文件已有标签。

VLM/人工只根据可见画面记录同一对象接触；像素重叠、靠近和后续运动不足以单独证明接触，不可判独立保留。新接触目标与旧运动/跌落目标的临界距离不可互换，必须使用同目标、同物理上下文、同源版本及同观察窗的边界。

## 登记与使用

执行 `python -m scripts.register_core100_contact_protocol` 产生独立的 `annotation_site/resources/core100_contact_protocol_20261027.json`，保留原catalog SHA256及十条原合同全文。其余90条合同不改动。

**100/100目标定义齐全不等于100条参考已准入，也不等于100条均为Near样本。** PairAcc只在合格异标签跨界对上计算；EventExact只能覆盖本次明确登记的接触链，不能宣传成完整终态因果链。

生产标注升级须保存原协议哈希及标注，逐项核对事件语义、媒体与窗口后才可登记继承；没有迁移凭据就不能在新协议下使用旧标签。自动判读不替代最终人审。新协议登记本身不自动迁移线上批次或授予评分资格。

## 本轮参考核验规则

新十条的接触诊断窗登记为条件帧起5秒：沿用多数现有生成输出及人工任务的5秒窗；参考两段接触都落在该窗内。原生时长不足单列，不变速或补零。旧标注窗口不同的记录需要重新核对，不能无时间依据地转移正事件或质量失败。

补充遥测与原轨迹的核对继承已有1毫米位置门槛，不放宽该数值。对于“至少发生一次”的正事件，首次接触之前及该接触帧的状态需要一致，并检查原参考RGB；首次接触之后的漂移仍完整报告，不把它称为全轨迹重现通过。负事件则需要核对完整登记窗和完整接触遥测。此处是证明已有正接触的核对范围，不缩短模型评测窗，不通过选择生成结果来定窗。

这类重放得到的接触记录始终标为新版本遥测；原文件、全程差异、首次偏差帧和源码哈希均保留。参考RGB若不能确认对象与接触、源版本不一致或接触前核对失败，仍不准入。
