当前p25两张尝试使用的卡均无法新建CUDA上下文，独立16元素CUDA探针也返回`No CUDA GPUs are available`。失败尝试及日志保留，没有重置共享显卡。p26/p29另有在运行的计算任务；不能将新进程失败记为物理事件结果。

## 指标与统计

1. **NearAcc**：使用已准入且整个归一化距离区间落在 `[0,0.05]` 的参考；每点多个种子先平均，再对参考正/负标签各平均，最后各占一半。分桶跨界的参考保留，不取区间中点强行分桶。输出近桶参考点数量、样本数量、两侧分数与覆盖。
2. **PairAcc**：四组新替换对使用独立、互不重叠种子流，分数为两端正确率之积。T11新事件两侧已复读并接入，独立配对准入为4/4。原T17、两组T19及恢复的原T03/T07/T14 cf-A、T15 cf-B使用共享种子时报告 `coupled_pair_accuracy`，按同一种子两端都成功计算；两者分开，不混算。共登记11组，11组已满足当前参考准入；不任意拼同场景样本。
3. **EventExact**：此入口只对应原协议中的临界事件子集。单个目标或部分事件全对只作诊断，不当作完整因果链EventExact。完整链仍使用原事件合同、全部标签和时序约束，当前入口返回 `event_exact=null`。
4. **BoundaryError**：当前100条任务未登记足够生成参数网格来估计模型阈值，因此返回空值和原因；不能用一对结果假装估计出模型的精确临界点。
5. **物理反演**：准入和拟合继续独立报告；临界流水线不重新决定既有反演协议的适用性，也不因为待核验而删除生成任务。`prepare --inversion-registration PATH`可附加已经验证的独立反演登记，逐项检查当前参考SHA、观察窗、拟合子窗口和协议来源，并固定该登记的SHA。没有该登记时显示“待验证”，不显示为“不适用”。随后`score --gravity PATH`接入原反演预测，仍报告全注册覆盖率、反演准入率及准入子集拟合覆盖率；原始重力只作评分，不交给质量/事件裁判。

评分同时导出 `distance_strata`：Near/Mid/Far及跨桶不确定组各自的参考正负数量、最终裁决数、普通准确率和平衡准确率。一个组缺少参考正类或负类时，平衡准确率为空。此表是描述性分层；不同场景混合后的Near/Far差异不能直接证明距离的因果效应，后者仍需同上下文的距离对照。

质量或生成失败仍留在已登记的模型评分分母，贡献零成功；尚未最终裁决的预标注单列待复核，正式分数返回空值，另给清楚标记的成功率下界。参考端缺真值依据的案例不作模型错误，但保留在100条总清单，单列参考覆盖。所有模型使用相同参考准入及配额；按来源上下文统计置信区间，重复种子不当成独立场景。

## 从生成到评分

```powershell
python -m physedit.core100_critical prepare --out review/core100_v2_run --model MODEL_NAME --fps 24 --variant 1 --seeds 0 1 2
```

输出300条任务，100个输入案例均保留。三种英文文本任选同一种跨模型比较。新8条使用独立种子流，其他已登记共享种子配对仍采用共享种子。每条要求真实原生帧数覆盖各自物理观察窗；不能通过改FPS、补帧或循环凑时长。确认模型原生支持后，在 `spec.json` 填写已有runner的 `generation_command`：

```powershell
python -m physedit.boundary run --spec review/core100_v2_run/spec.json --run-dir review/core100_v2_outputs --execute
python -m physedit.boundary screen --run-dir review/core100_v2_outputs --judgements vlm_judgements.jsonl --reviews quality_reviews.jsonl --out-dir review/core100_v2_screened
python -m physedit.core100_critical score --run-dir review/core100_v2_outputs --screening review/core100_v2_screened/screening.jsonl --annotations final_event_annotations.jsonl --out review/core100_v2_scores.json
```

导出包中的 `judge_protocol.json` 已按100条各自的原事件定义绑定，包括新版8条的对象和数值判据。不能按同名槽位套用旧参考的对象定义，例如新T04仍明确使用`t04v3`对象。裁判只接收生成视频、指定观察窗、对象和事件定义，不接收参考标签、临界值、侧别或距离。带物理单位的事件需要生成视频自己的标定/轨迹依据，缺测量时转人工或保留不可判，不能借用参考状态替生成视频测量。

接入现有两阶段裁判，推荐使用专门的适配入口：

```powershell
python -m physedit.core100_critical judge --run-dir review/core100_v2_outputs --protocol review/core100_v2_run/judge_protocol.json --out-dir review/core100_v2_judged --quality-predictions quality_predictions.jsonl --event-predictions event_predictions.jsonl --reviews human_reviews.jsonl
```

两类预测文件沿用已有独立质量筛查和逐事件判读格式。也可以在协议中设置已有`quality_command`、`event_command`，添加`--execute`执行。高置信度只产生预标注；人工明确确认主事件后才写入`critical_annotations.jsonl`的`review_status="final"`，其他事件各自保留状态。该入口保留旧通用诊断文件，最终临界分数写入`scores.json`。没有人工记录时仍能生成预标注/复核队列，但不自动得到正式准确率。

遵循原有[两阶段筛查](TWO_STAGE_PIPELINE.md)、[失败分母规则](FAILURE_HANDLING.md)和[窗口约束](WINDOW_AWARE_JUDGE.md)。`screening.jsonl` 使用原标准格式：`sample_id`、`video_sha256`、`status`、`method`、`evidence`；确认失败须有 `reviewer` 与阻断范围。事件标注须绑定同一视频哈希，并保留证据；高置信预标注仍以 `review_status="prelabel"` 保存，最终裁决后使用 `review_status="final"`，事件值为0/1/空。自动转最终裁决前须满足既有裁判验证政策，不能把模型自报置信度当作验证结果。

新8条必须新生成、新标注。其余92条只有参考、图片、实际提交文本、种子、原生窗口和协议匹配时才复用；不能只凭槽位ID迁移旧成绩。`registered.json` 固定实际使用的临界表路径及哈希，后续追加证据不会重写旧运行的协议。

本轮测试以合成媒体和明确标记的单元测试标签核验分母、配对与版本约束；不产生模型能力结论。目前仅预检查生成计划，尚未执行新模型推理。
