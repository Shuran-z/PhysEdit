# 观察窗感知的事件裁判：开发版

2026-10-17：新增[双职责协议](DUAL_JUDGE.md)，区分质量筛查与每个事件的置信度、证据及预标注/复核。本文件的抽帧与轨迹检查仍作为辅助模块。

本模块用于临界边界事件标注的辅助判读。它不替代数据集的物理参数真值、临界搜索记录或 GravTrace 反演；当前是诊断适配器，尚未默认接管正式 benchmark 评分。

## 处理顺序

1. 固定目标、视频版本与观察截止帧，保留全部登记样本。
2. SAM2 使用首帧框/点定位，保留逐帧框和跟踪丢失记录。非空掩膜不是身份或接触真值。
3. 保留5个全程时间锚点，在最大相邻帧框中心运动附近补充8个时间点；计算只使用观察截止前轨迹。当前共至多13个时间点。最大运动可能来自跟踪错误，这只是候选采样策略。
4. 每个时间点的全图、局部图旁边直接标出同一个帧索引。Qwen先逐时刻判断目标位于初始桌面、空中、地面、遮挡、画外或不确定，以及身份是否可追踪；不直接输出分数。
5. 程序整理三个事件，并检查格式、时间顺序、目标运动与文字判断的明显冲突。
6. 输出候选事件标签、逐事件路由及人工复核队列。人工记录保留审核人、证据时间、原因和观察窗。

## 三个事件分别处理

- **脱离初始支撑**：先在初始桌面，后有可辨认的完全分离画面。部分越缘、倾斜不能直接算脱离。
- **脱离后下落**：需要空中状态跨两个不同时间点以及向下运动证据。不要求落地。
- **地面接触**：单独判断，不把初始桌面叫作地面。不观察到落地不等于最终不会落地。一个视频的地面接触待复核，不会自动撤销已经具备证据的上游事件候选标签。

“未发生”的负标签仅在预先声明的观察窗内解释；最终结局评测还需要该观察窗满足任务预定时长。源视频在事件完成前结束、生成输出损坏和裁判看不清，是三种不同原因，不能混记。

## 人工复核触发

- 模型输出格式错误、时间点缺失、索引不对应。
- 身份或位置不确定，或不足以支持正/负事件判断。
- 声称始终在桌面，但跟踪竖向变化明显，或相关跟踪缺失。
- 声称已在地面，但对应轨迹仍大幅竖向变化，或缺少对应跟踪，需要重新核查接触。

这些轨迹检查只能触发复核，不能强制改判为跌落或未跌落。当前像素阈值是开发启发式：下落候选位移>3px、桌面冲突>max(12px,1.5倍初始框高度)、地面冲突>max(12px,0.5倍首个地面候选框高度)。它们尚未验证跨分辨率、相机运动、透视及弹跳场景；不应作为通用物理定律。地面冲突检查可能把真实落地后弹跳/滚动送复核，这是可见的代价。

## 统计和留档

- 每条输入保留原始模型回答，后处理不修改原件。
- `candidate_usable` 表示通过当前程序检查，不等于独立人工确认正确。
- 人工待审样本保留在登记总数中；待审期间不能把未知事件填0或将其删除。
- 分别报告逐事件候选覆盖率、复核率、生成失败率与人工确认后的分数。地面接触 `not_observed` 不直接计作一个可靠的最终负标签。
- 本模块没有执行物理反演；不能把事件可判率当成反演覆盖率。
- 独立验证应比较人工一致性、错误放行、误拒和复核工作量。当前五个开发输入不构成独立验证集，且两个截短版本与原片共享轨迹。

## 代码入口

- `physedit/boundary_window.py`：抽帧、事件整理及复核规则。
- `scripts/prepare_qwen_window_v2.py`：生成诊断运行器。
- `scripts/collect_window_review.py --run review/qwen35_window_v2_20261016`：保留总分母并导出路由/复核队列。
- `scripts/build_window_review_page.py`：生成本地人工页面和严格截止的前缀视频；需含OpenCV的环境。
- `tests/test_boundary_window.py`：未来帧隔离、无落地的下落判读、矛盾转复核、上游事件保留。

实验结果见 `review/qwen35_window_v2_20261016/RESULTS.md`。该实验同时改变了抽帧和提示词结构；即便改善，也不能单独归因于某一项。
