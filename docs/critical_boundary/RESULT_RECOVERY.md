# 远端求解结果回收

执行入口：`python -m scripts.run_boundary_result_integration --watch --hours 72`。
这是有时限的当前任务执行器；不表示 20 个场景已经完成，也不自动批准参考视频进入正式评分。

## 超时处理

- 按主机隔离查询。一台机器失联时，其他主机的结果仍继续回收。
- SSH 设置连接及存活时限，传输失败最多尝试两次。远端哈希或参数校验失败不作为网络故障重试。
- 首次完整检查状态、压缩文件及配置的哈希；后续仅在预期哈希和文件身份均未变化时复用校验。文件变化后重新计算完整哈希。
- 三个独立收集器可同时运行；它们结束后才合并距离。后处理失败会在下一轮重试，即使远端结果没有变化。
- p29 共享存储不可连接时，只读文件校验可以通过 p26 访问同一绝对路径；执行主机身份保持原记录。此回退不用于查询另一主机的进程。

## 本轮任务

四个 `five_scene_parallel_*_launch_20261021.json` 记录将原队列中未尝试的 315 项分给四个 worker。已完成、已失败和中断时产生的文件均保留；没有删除原计划或重写发布标签。

`t13_remaining_seeded_scans_launch_20261021.json` 记录 8 项补充任务。使用原完整渲染入口、显式种子 0 和同上下文的实际发布参数范围。种子 0 是新补充设置，不是找回的原始种子；结果进入诊断文件，不覆盖原发布区间或计入原始细化完成数。

T19 新版仍在渲染，旧视频继续停用。T14 使用用户指定的旧笔穿通道版本，T14S 单列。

## 后续恢复

- `register_t13_seeded_supplement` 校验完整渲染入口、配置/状态哈希和实际初始化种子，计算新 seed0 轨迹的条件区间距离；原发布标签、ID 和边界另存。未观测翻转的补充轨迹保留，不伪造距离。
- `audit_t11_remaining_failures` 对已有失败端点逐条比较原状态及复跑状态，区分物理配置差异、接触前轨迹偏移、接触触发时刻与施力帧数差异。它不把观测到的差异当作已经证明求解器内部的唯一原因。
- `launch_boundary_timeout_retries` 将尚未成功的三项执行超时任务迁移到 T10 释放的 GPU1，增加执行时限，不改变物理参数或事件标签。
- `recover_t18_resource_queue` 仅停止身份核实过的本任务 T18 进程组，保留旧状态快照及完成文件。新 worker 在显存不足时等待；暂时的资源不足不再标成物理求解失败。原结果和探针可复用，legacy 队列改用 GPU1。
- T18 回收器直接检查规范完成文件，即使重启 worker 的临时状态表尚未走到该任务，也不会丢失已完成结果。多个执行根目录出现相同任务时，失败重试不覆盖已完成结果。
