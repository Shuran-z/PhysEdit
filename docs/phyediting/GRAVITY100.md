# 条件帧重力评测

本协议包含100条单视角重力任务，覆盖T01–T20，每类5条。使用[清单CSV](gravity100.csv)固定样本、机位、条件帧与评测长度；同一条任务在所有生成模型中使用相同输入和时域。

| :---: | :---: | :---: |
| ID | T01、T02、T04–T10、T12–T18 | 80 |
| OOD-1 | T03、T20 | 10 |
| OOD-2 | T11、T19 | 10 |

| 维度 | 分布 | 数量 |
| :---: | :---: | :---: |

| 背景 | bg01 / bg02 / bg03 / bg04 | 25 / 25 / 25 / 25 |
| 机位 | cam01 / cam02 / cam03 | 34 / 33 / 33 |
| 重力（m/s²） | 1.62 / 3.71 / 9.81 / 15 / 24 | 21 / 21 / 21 / 20 / 17 |

T09、T10、T14的第5条分别采用3.71、9.81、1.62 m/s²，具体成员以CSV为准。25条复用开发样本，75条为新增条件测量；集合标签表示场景分组，开发使用情况由`reused_development`逐条记录。

## 条件帧与时间

每条任务的条件图即参考片段第0帧。生成与跟踪从该图开始，评测使用第0帧至`evaluation_frame_count - 1`的完整连续区间。每条时域预先固定，所有模型沿用同一范围；生成后不另选动作起点或截取误差较小的窗口。

原视频的裁取位置由`source_condition_frame`和`source_last_frame`记录。前者对应任务第0帧，用于重建条件片段；生成视频无需等待原视频中的前导时长。参考片段为30 fps，长度为2–64帧。

物理时间沿用来源任务登记的步长，与媒体时间分别处理。部分来源的物理步长为0.02 s，而媒体帧间隔为1/30 s；测量保留两者的映射。不同生成帧率按相同时间范围对齐，不直接把视频帧率替代物理时钟。输出不足固定时域、缺帧或解码失败时保留任务并记录原因。

## 测量与统计

重力从单视角目标轮廓或表面RGB运动估计。使用该条登记的条件帧几何、位姿、相机、初始运动和已知控制；重力真值、其别名及未来物理状态不进入估计器。估计器只接收匿名任务ID与经过筛选的测量输入；来源名称和CSV中的评分字段由数据加载器与评分器读取。

本清单只评测重力。动摩擦和初速度在这些任务中属于已知条件或相应模型的辅助变量，沿用各自的测量协议统计。

逐条相对误差为`100 × |估计值 − 真值| / 真值`，单位为%。每组报告逐样本平均误差、最大误差、失败率、数值输出覆盖率和有效测量覆盖率。失败和不适用项保留在固定分母中，误差统计的有效数量同时列出。

## 清单使用

CSV的`id`为稳定任务编号；`sample_id`、机位、原视频帧号及SHA256用于定位与校验来源。`reference_video_sha256`对应从条件帧开始的无损参考片段，`conditioning_image_sha256`对应其第0帧图像。重力字段单位为m/s²，所有帧号从0计数。

## 一键运行

任务目录包含条件图、参考片段、逐条已知条件和测量定义，入口为`tasks.jsonl`。先填写[模型配置](../../examples/phyediting/gravity100.model.example.json)，再创建运行配置：

```bash
physedit prepare-gravity100 /path/to/tasks.jsonl --model-config model.json --out gravity100.json
physedit plan gravity100.json
physedit run gravity100.json --execute
```

`prepare-gravity100`校验完整100条成员及文件SHA256，将条件帧固定为0，并绑定独立的媒体与物理时钟。`plan`显示输入齐备数、各模型原生帧率下的观测数量和逐条不足原因。执行时沿用模型登记的帧数、帧率、采样参数及固定种子20261008。

GPU阶段默认要求设备空闲。允许共享时，在`generation_runtime.gpu_sharing`中填写`allowed_gpu_uuids`、`minimum_free_mib`和`maximum_utilization_percent`，分别限定设备、剩余显存和已有负载。运行前重新读取资源，超出范围则保留输出并暂缓，不终止已有进程。

轮廓、表面RGB和接触动力学使用各条登记的测量模型。T02的耦合运动通过`native_runtime.command`连接CPU PhysX后端，按当前视频观测重新搜索重力；后端程序为[`native_physx_worker.py`](../../physedit/native_physx_worker.py)，使用CPU容器运行并校验源码SHA256。跨主机部署可用[`native_bridge.py`](../../physedit/native_bridge.py)转发固定后端会话；连接使用Unix socket，不传递登录凭据。参考视频的观测、估计值和自适应搜索候选不进入生成视频的估计过程。

低帧率模型在短时域内的观测可能少于测量所需数量。这类任务保留身份与原因，计入覆盖率和失败率的固定分母。物理测量使用实际解码帧及其时间戳，保留原帧率。顺序读取模型使用固定范围内的无损帧前缀；不插入观测帧，也不改变播放速度。离散控制模型同时检查原物理子步与观测时刻是否兼容。

PhysRVG将同一条件图重复为五帧静态输入。评测以给定前缀的最后一帧为时间零点：保留49帧原生输出，并从第5帧开始无损导出45帧评测视频，帧率保持15fps。SAM跟踪、重力反演、V/P指标和Qwen使用同一评测视频；起点由模型的条件输入机制确定。其余模型从原生输出第1帧开始评测。

重力结果按ID、OOD-1、OOD-2汇总。选用V/P时，参考图像比较与配对轨迹使用该条固定时域；1秒指标在时长足够的任务中统计。Qwen判断整段生成视频的视觉与物理表现。已有运行可用`physedit evaluate gravity100.json --run-dir runs/gravity100 --out runs/recheck --execute`重评选用的V/P和Qwen，并读取该次生成视频的重力结果。

数据集核心协议与训练来源分配见[评测划分与联合训练](../joint_split_v3/PROTOCOL.md)。
