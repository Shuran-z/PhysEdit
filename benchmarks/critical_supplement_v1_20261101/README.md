本集从已发布视频选择 T04、T05、T10、T11 各一组异侧结果，共 **8 条参考视频、4 组配对**，用于先验证临界响应评测能否区分恒定结局和正确参数响应。用户已确认保留 Core100 并追加本集。它不修改 Core100 的输入、参考、提示词、人工标签或模型结果；两套结果分表报告。

统一入口为 `catalog/active_critical_supplement.json`。源视频固定于 `phy2/phydataset@2d78126612b10a9aeb122b967084036c4d9f378f`；原状态与源视频逐条核对。清单中的下载路径、视频 SHA256、原 metadata SHA256 和物理时钟均在 `reference_ledger.json`。条件图均来自原视频第 4 帧。`conditions.json` 保存每条自己的三种简短英文提示词及哈希，`answers.json` 单独保存结果；生成导出不会包含答案、边界或参考完整视频。

三种提示词包含相同物理输入和必要控制，仅开头措辞不同；同一配对使用相同字段，不因文本预算在一侧额外透露质量或摩擦。完整参数继续保留于 metadata。实际 T5/UMT5 tokenizer 已计数，全部文本分别满足 LTX 120、CogVideoX 218、Wan 504 token 预算，不做截断。

当前训练清单中，选定视频哈希及来源组均未进入 `train_final`：T04/T05/T10 属测试/候补保护来源组，T11 属 OOD 留出。该检查不能代替每个已有模型 checkpoint 的实际训练数据核对。本集只有四个场景来源上下文，不能当作八个独立上下文或最终大规模主实验。

## 距离和指标

两条已发布视频的参数构成**观测到的局部异侧区间** `[a,b]`。不取中点冒充精确临界值，也不证明整个参数域只有一次翻转。对视频参数 θ，在原参数域跨度 S 下保留距离上下界：

`d_low = distance(θ,[a,b])/S`，`d_high = max(|θ-a|,|θ-b|)/S`。

原域分别为 T04 `[0.08,0.14]`、T05 `[1.11,1.16]`、T10 `[0.08,0.217]`、T11 `[1.8,3.6]`。只有整个距离区间落入同一桶才分桶；不会为凑 Near 扩大归一化域。

- **NearAcc**：近桶正、负参考标签的生成成功率各占一半。当前只有 T10 两条符合 Near（距离上界约 0.04745）。T04、T05、T11 的区间跨桶，仍保留用于配对。
- **PairAcc**：同组两端使用不同独立种子，分别估计正确率 A₁、A₂，组分数为 A₁×A₂，再平均四组。不是共享种子的翻转率。每侧至少生成多次，置信区间应按来源上下文/组处理，不能把重复种子算作新上下文。
- **完整 EventExact**：本集尚未登记完整事件链及全部时序，不报告此指标。单个目标事件全对仅作为目标一致性诊断，不能改名为完整因果链分数。
- **物理反演**：八条均登记为 `pending_reference_validation`，尚无反演成绩。它不阻止两侧生成和事件评测；独立报告反演准入与拟合覆盖率。

质量失败、生成失败和最终未裁决样本留在预登记总分母；相应成功贡献为零，同时报告质量失败率、事件可测/已裁决覆盖率及人工待复核数。原始拒绝原因与证据保留。目标明确但其他外观细节有问题，不能擅自改写已登记事件真值。

## 观察窗口与准入

八条已完成源视频/原状态一致性核对，并由助手结合画面和状态检查指定事件。这个准入只适用于本次目标参考，不等于独立人工一致性验证、整段物理认证或 Qwen 裁判已验证。

源媒体播放 FPS 与物理状态时钟分开记录。条件帧后的静止保持按原媒体时钟计算，实际运动按 `dt×steps_per_frame` 计算；明确给生成器初始保持时长与释放后的速度/力。T10 媒体 30fps，但活动状态间隔为 0.02秒；第4帧之后剩余13帧静止加192帧活动，物理窗口为 `13/30+192×0.02=4.273333秒`，不能全部按0.02秒或媒体FPS计时。其他三组两种时钟相同。

T05 完全通过需要原 6.833333秒窗口；现有固定 124帧/24fps 的旧 H3 适配器不能覆盖它。生成端必须支持所选原生帧数及物理时长，禁止改 FPS、加速或截短窗口去凑通过；不支持时报告窗口覆盖失败，不能记为“未通过通道”。

## 运行

在仓库根目录执行：

```powershell
python -m physedit.critical_supplement status
python -m physedit.critical_supplement export --out review/critical_supplement_run --model MODEL_NAME --fps 24 --variant 1 --seeds 0 1 2
```

导出包含 24 条生成任务（8条×3种子）和独立答案表。对比模型使用相同提示词变体及配额；不要混用不同文本的成绩。`spec.json` 未预填模型命令：确认模型原生时长、分辨率与帧数支持后填写 `generation_command`，再执行通用生成和两阶段筛查流程：

```powershell
python -m physedit.boundary run --spec review/critical_supplement_run/spec.json --run-dir review/critical_supplement_model_outputs --execute
python -m physedit.critical_supplement score --run-dir review/critical_supplement_model_outputs --screening screening.jsonl --annotations event_annotations.jsonl --out review/critical_supplement_scores.json
```

筛查/标注格式沿用 [两阶段协议](../../docs/critical_boundary/TWO_STAGE_PIPELINE.md) 与 [失败分母规则](../../docs/critical_boundary/FAILURE_HANDLING.md)。每个事件保留置信度和证据，含糊、矛盾或不可观察的结果进入人工复核；质量筛查失败不物理删除、不移出总分母。不得将原答案表当作生成视频的人工标注。

当前交付的是可运行的参考与评分输入，**实际模型生成数为零，没有新的模型分数**。单元测试中的合成标注只验证计算和失败分母处理，不是实验结果。
